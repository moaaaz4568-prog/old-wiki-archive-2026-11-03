# دورة المصدر من `new` إلى الإغلاق

## عقد 2026-10-10

اقرأ [معاني R/T/C/K/M/QA](../INDEX.md) و`<alignment_path>` والملحق في
`<user_messages_path>`؛ المواءمة الأحدث تحكم الحالات التالية، لا التسلسل القديم.

- `route_done` مسموح قبل extraction بعد full semantic read وتصنيف ونسخة
  مستقلة byte-exact في `done/<domain>/<subdomain>/` مع hash متحقق. النسخة
  المادية افتراضية؛ `source_refs` فهارس ثانوية فقط. `done` لا يعني `domain_done`.
- الفرز والنسخ عامان لأي domain؛ المعرفة في `current_domain` فقط، والباقي
  `queued` لا quarantined. quarantine لفساد/تعذر قراءة/هوية غير موثوقة؛
  غموض التصنيف uncertain. احفظ اختلاف الآراء مع scope بدل استبعاده.
- أثناء القراءة الاستخراجية اجمع terms وcandidate Claims معًا بمواضعها، دون
  انتظار قراءة المجال كله. Concepts من أدلة مراجعة، ولا اختراع تعريفات.
- `source_done` استخراج كامل terms/Claims مع QA؛ لا يتطلب Concepts أو Master.
  `subdomain_extraction_done` ليس T: يلزم `domain_terms_complete` لكل المجال
  قبل أي Master حتى الصغير، بلا sample أو snapshot يستبعد مرشحًا دون قرار.
- `delta` تجعل التغطية `stale` وتُجدول في queue؛ فقط `domain_done` يسمح بمعرفة
  التالي بعد مراجعة أثر الوصول الجديد، ولا يفتح مجالين.

## عقد التشغيل القابل للتهيئة

ثبّت هذه القيم قبل كل دفعة، وسجّل نسخة الإعداد في checkpoint:

```text
WIKI_ROOT                = <wiki_root>
NEW_ROOT                 = مسار الاستقبال المهيأ
RAW_ROOT                 = مسار الدليل الخام المهيأ
SOURCE_RECORD_ROOT       = مسار سجلات Source المهيأ
ROUTING_LOG_ROOT         = مسار سجلات route المهيأ
DONE_ROOT                = جذر سجل done المهيأ
QUARANTINE_ROOT          = مسار مراجع العزل المهيأ
STAGING_ROOT             = مسار manifests وcheckpoints المهيأ
DOMAIN_CATALOG_PATH      = catalog المجالات والأقسام
DOMAIN_STATE_PATH        = سجل المجال المفتوح والقفل
LAYER_GATE_CONFIG_PATH   = تعريف بوابات الطبقات المطلوبة
RUN_ID                   = معرف دفعة ثابت
```

اقرأ تعليمات المشروع وschema والميثاق ومواصفة التوجيه كاملة. استخدم قيم
placeholders الحقيقية قبل التنفيذ؛ القوالب ليست سجلات نجاح. لا تُنشئ مجلدًا
لمجرد وجوده في مثال. اجعل كل path مسجل نسبيًا إلى `WIKI_ROOT`، بلا `..` أو مسار
مطلق، وتحقق من المسار الفعلي بعد حل الروابط الرمزية. لا تنشر كتابة خارج الجذر.

## الحالات المستقلة

```text
كل domains: full semantic read + hash/dedup + classification + verified copy -> R/route_done
غير النشط: knowledge_state = queued
current_domain: reading + terms/candidate Claims -> review/QA -> source_done
كل مصادر الفرع المستخرجة -> subdomain_extraction_done
كل مصطلحات المجال وكل فروعه مراجعة -> T/domain_terms_complete
Claims مراجعة -> K/Concepts؛ T + C/K ذات الصلة -> M/Master؛ المخرجات + QA -> domain_done
```

خزّن هذه الأبعاد في workflow، لا قيمًا مخترعة في Source.status. إذا كان العقد
يستعمل `route_status: done` فاربطه بـroute_done فقط، مع مرجع إثبات R. `processed`
ليس اكتمال استخراج، ووجود البايتات الأصلية في new بعد النسخ ليس عملًا مفتوحًا
بالضرورة. استبدل استعمال `subdomain_done` الملتبس بحالة الاستخراج الصريحة.

## الإجراء

### 1. الاستقبال والجرد

1. أنشئ `RUN_ID` ثابتًا للدفعة، وجرد الملفات العادية تحت `NEW_ROOT` وأي input
   root مصرح به، مع المسار النسبي والحجم ووقت الجرد.
2. افحص traversal والـsymlink والحدود. سجّل العنصر غير الآمن كعزل مرجعي ولا
   تنقل الأصل.
3. ثبّت هوية work item في سجل الاستقبال؛ أنشئ Source مطابقًا للschema بعد قياس
   البصمة الحقيقية. لا تملأ `content_hash` بقيمة وهمية ولا تعِد استخدام
   `source_id` لمحتوى مختلف. اربط السجل القائم إن كان قابلًا للتحقق.
4. أبقِ المصدر في مكانه الأصلي طوال الدورة. الانتقال من `new` إلى `done` انتقال
   في سجل المعالجة، وليس `move` للدليل الخام.
5. نفّذ القراءة والتصنيف والنسخ العام حتى للـdomains المنتظرة. لا تبدأ استخراج
   مجال غير نشط؛ اجعل حالته المعرفية queued مع بقاء R ناجحة إن استوفت شروطها.

### 2. القراءة الكاملة وتثبيت الهوية

1. خذ `stat` قبل القراءة، اقرأ كل البايتات حتى EOF، واحسب SHA-256 على البايتات
   الأصلية قبل أي تطبيع.
2. سجّل `bytes_expected`, `bytes_read`, `eof_reached`, الترميز، عدد الاستبدالات
   إن وجدت، وحالة الثبات بعد القراءة.
3. أعد فحص الحجم والبصمة بعد القراءة. إذا تغير الملف أو تعذر إثبات EOF أو ظهرت
   بدائل ترميز صامتة، أوقف الانتقال وسجّل سبب العزل.
4. لا تعتبر البصمة وحدها دليلًا على صلاحية النص الدلالي. الملف الفارغ أو الثنائي
   غير المدعوم أو القراءة غير المكتملة يبقى خارج `source_done`.
5. اقرأ المحتوى دلاليًا كاملًا في مقاطع متتابعة عند الحاجة، وسجّل تغطية المقاطع
   بلا فجوات وربطها بنفس hash. لا يعدّ hash آلي أو نص أداة مبتور إثباتًا لذلك.
   عند استعمال parser موثق، احفظ نسخته وخرائط مواضعه إلى الخام دون تغيير الخام.

### 3. كشف التكرار

قارن البصمة مع كل عناصر الدفعة، وسجلات Source القابلة لإعادة الحل، وmanifests
السابقة، وartifacts الموجودة في `DONE_ROOT`:

| النتيجة | القرار |
|---|---|
| `unique_hash` | أكمل كسجل أساسي بعد التوجيه |
| `exact_duplicate` | اختر سجلًا أساسيًا وسجّل `duplicate_of` لكل نسخة |
| `same_name_new_hash` | اعتبرهما مصدرين مختلفين |
| `possible_normalized_duplicate` | لا تدمج تلقائيًا؛ أرسل إلى `uncertain` |
| `identity_conflict` | اعزل تعارض الهوية إلى أن يُحسم |
| `stale_reference` | سجّل مرجعًا قديمًا؛ لا تثبت التكرار من مسار مفقود |

اختر المصدر الأساسي حتميًا: سجل قائم قابل للتحقق، ثم الأقدم في الدفعة، ثم
المسار النسبي المرتب. لا تحذف النسخ التابعة؛ اربط duplicate بنفس الهوية
والنسخة المصنفة المتحققة، ولا تنتظر Master لإغلاق مرجع التكرار.

افصل عدّ المسارات عن عدّ البصمات الفريدة. لا تعِد استخراج المحتوى المكرر كدليل
مستقل، ولا تستعمل سجل hash قديمًا بلا تحقق من مصدره. إذا تعذر ذلك يبقى unresolved؛
المسار المفقود دون نسخة قابلة للتحقق يُعزل، ولا يُعاد إنشاء الدليل بالتخمين.

### 4. التوجيه وartifact الآمن

استدعِ `domain-discovery-and-routing` أو عقد التوجيه المهيأ. لا تنتقل إلى
`classified` إلا بزوج primary واحد، أو اترك المصدر `uncertain`.

انسخ البايتات نفسها إلى `<wiki_root>/done/<domain>/<subdomain>/<source_id>.<ext>`
قبل استخراج المعرفة. لا تستخدم `done/<domain>/source_refs/<subdomain>/` بديلًا،
ولا تؤخر النسخة لوجود Terms أو Concepts أو Master. الأصل يبقى immutable.

تحقق أن الوجهة ملف عادي مستقل: ليست symlink أو hardlink، وليست نفس ملف الأصل؛
قارن SHA-256 للنسخة والأصل وثباتهما. امنع overwrite: إذا وُجد الملف متطابقًا
أعد استعماله، وإذا تعارض الاسم/البصمة أوقف R وسجّل السبب. لا تُسمِّ تعارض
وجهة كتابة فسادًا للأصل تلقائيًا. سجل failure نوعه الفعلي.

أرفق route record وفهرسًا محليًا يربطان `source_id`, `source_path`, `copy_path`,
`source_hash`, `copy_hash`, read_audit، dedup، primary/secondary، ودليل النسخ
والاستقلال. reference إضافي مسموح لكنه لا يحل محل النسخة المادية. كل paths
في السجل نسبية إلى الجذر، مع رفض traversal وإعادة فحص الوجهة قبل الكتابة.

### 5. R ثم إغلاق استخراج المصدر، بلا اعتماد دائري

لا تسجل `route_done` إلا بعد فحص:

- Source ID فريد ومسار نسبي آمن.
- قراءة كاملة ثابتة وEOF مثبت.
- SHA-256 قابل لإعادة الحساب ومطابق.
- نتيجة dedup واضحة، مع `duplicate_of` عند الحاجة.
- primary route واحد صالح، والمراجع الثانوية مفسرة أو `[]`.
- نسخة byte-exact مستقلة في المسار المصنف وبصمتها مطابقة للأصل.
- لا تعديل في `RAW_ROOT`، وفهرس المسار المحلي محدث.
- لا توجد ملاحظة حرجة مفتوحة تمنع مسار المصدر.

الفحوص G0–G8 القديمة يمكن أن تسند R بعد مواءمة G7 مع النسخة المادية، ولا
تغني عن T/C/K/M/QA. لا تعلن تنفيذ فحص غير متاح أو نجاحه دون مخرجات.

لا تسجل **`source_done`** إلا بإضافة إثباتات المعالجة المعرفية:

1. لكل جزء مقروء مصير: مصطلحات/Claims ومراجع مخرجاتها، أو عدم احتوائه مادة
   قابلة للاستخراج مع سبب وموضع؛ لا توجد فجوة استخراج حرجة أو جزء غير مقروء.
2. استُخرجت terms وClaims كاملة ورُوجعت على مستوى هذا المصدر مع provenance
   وscope ونوع الدليل وتقييمه. ليس مطلوبًا T لكل المجال ولا K ولا M لهذا الإغلاق.
3. راجع QA مستقل التغطية والمساهمات والمرفوضات والخلافات. اكتمال التقييم لا
   يعني اتفاق الآراء؛ تحفظ الآراء المتعارضة المراجعة بحالتها وحدودها.
4. سجل قرار source_done ومراجع مخرجاته بعد QA. الملف المصنف موجود أصلًا منذ R؛
   لا تنشئ نسخة ثانية عند إغلاق الاستخراج، ولا تغيّر الخام أو حدود الاقتباسات.

سجّل `source_done_at`, و`run_id`, ومراجع بوابات الطبقات ونسخة verifier ومسار
قرار QA في closure record. مصدر مرفوض إداريًا له disposition مستقل ومسبب؛ لا
يسمى `source_done` معرفيًا. duplicate يُغلق بمرجع إلى الأساسي المقبول وبصمة
مطابقة، لا بمخرجات معرفة ثانية. لا ترفع Source إلى قيمة خارج schema.

### 6. `subdomain_extraction_done` ثم T لكل المجال

احسبها من manifest ثابت لا من وجود مجلد:

1. جرد كل المصادر التابعة للـ`subdomain` وبيّن ما في `new` وما في `uncertain` أو
   `quarantine` وما أُغلق.
2. تحقق من اكتمال استخراج ومراجعة كل مصادر الفرع في snapshot بكل قرارات
   الإدراج والاستبعاد. وجود owner أو next_action لا يحسم المرشح.
3. اجمع الفروع كلها لبوابة `domain_terms_complete`. snapshot يشمل جميع
   المرشحين ضمن حدود المجال المعلنة، لا فرعًا مختارًا أو sample. مرشح غير
   محسوم يمنع T، ولا يختفي بتغيير قائمة المصادر. لا Master صغيرًا قبل T.
4. حدّث فهرس الـsubdomain وسجل handoff وcheckpoint، واثبت أن الروابط والمسارات
   قابلة للحل.
5. لا تغلق استخراج الفرع مع مصدر مطلوب ناقص. لا تشترط Concepts/Masters لإغلاقه.

### 7. بوابة `domain_done`

لا تفتح إغلاق المجال إلا بعد:

- إثبات استخراج الفروع المطلوبة وT للمجال وC/K/M للمخرجات التي يعتمدها الإغلاق.
- عدم وجود مصدر تابع حالته `new` أو قيد المراجعة أو `uncertain` أو `quarantine`
  غير محسوم. القرار الإداري النهائي لا يمحو فجوة معرفة حرجة ولا يتجاوزها.
- نجاح بوابات T/C/K/M، لا إعفاء بوابة مطلوبة ولا Master draft/partial منشور كنهائي.
- تحديث فهرس الجذر وفهرس المجال وفهارس الأقسام والطبقات.
- وجود سجل إغلاق مستقل يربط المصادر بالمخرجات وQA والفهارس واختبارات الاسترجاع.
- عدم وجود ملاحظة حرجة أو رابط مكسور أو artifact لا يمكن التحقق منه.

`domain_done` لا يعني أن كل سؤال مستقبلي أُجيب عنه؛ يعني أن شروط الإغلاق
المعلنة قيسَت وسُجلت، وأن الفجوات غير الحرجة ظاهرة لا مخفية.

## إعادة التشغيل والاستئناف

- استخدم مفاتيح idempotency مثل `(content_hash, source_id, route_version)` لمنع
  إنشاء سجل ثانٍ لنفس العملية.
- اكتب manifest وcheckpoint مشتقين معًا بعد نجاح كل بوابة، وسجّل عدد المدخلات
  والقراءات والبصمات والتكرارات والعزل والإغلاق.
- عند الانقطاع، اقرأ آخر checkpoint، أعد التحقق من البصمة والمسارات، واستأنف من
  أول بوابة غير ناجحة. إذا تغيرت البصمة، افتح دورة جديدة للمحتوى الجديد.
- لا تكتب فوق سجل تاريخي عند تغير القرار؛ أنشئ إصدار تشغيل جديدًا واربطه
  بالسابق.
- كل وصول جديد delta، حتى لمجال سابق الإغلاق: علّم التغطية المتأثرة stale
  واحتفظ بدليل snapshot القديم تاريخيًا. يعالج النشط delta الخاصة به ثم يعيد
  T والبوابات المتأثرة؛ غير النشط يبقى queued. راجع أثر كل delta قبل أي انتقال
  معرفي، ولا تفتح مجالًا ثانيًا لمعالجتها بالتوازي.

## فحوص الإغلاق

افصل verifier دورة المصدر عن verifier طبقات المعرفة، ونفّذ على الأقل:

1. مساواة جرد `RAW_ROOT` قبل وبعد: المسار والحجم والبصمة.
2. إثبات القراءة الكاملة لكل مصدر وتطابق `bytes_read` وEOF؛ يجوز sampling
   إضافي لتدقيق الجودة، لكنه لا يعوض التغطية الكاملة أو البصمات لكل المدخلات.
3. حل كل `source_path` وartifact والتحقق من البصمة.
4. فحص عدم وجود مسار أساسي مزدوج لنفس المصدر.
5. تطابق الفهارس مع الحالات المستقلة: route_done ليس source_done ولا domain_done؛
   وsubdomain_extraction_done ليس تصريح Master.

## حالات الرفض والاستئناف — متوقعة وليست نتائج منفذة

- اسم واحد ببصمتين: هويتان، بلا overwrite؛ بصمة واحدة بمسارين: canonical وduplicate.
- مصدر مقطوع أو متغير أو مرجع مفقود: quarantine reference، بلا نقل الخام.
- R ناجحة واستخراج جزئي: route_done فقط؛ terms/Claims كاملة مع QA وبلا Master:
  source_done جائز، لكن ليس domain_done.
- مصدر غير نشط مصنف: نسخة done صحيحة وحالة معرفة queued، لا quarantine.
- فرع مكتمل وبقية مصطلحات المجال ناقصة: لا Master حتى الصغير.
- إعادة نفس الدفعة أو انقطاع بين artifact والفهرس: تحقق وأكمل الجزء الناقص،
  دون تكرار السجل أو نشر حالة إغلاق قبل اكتمال الحزمة.

## ممنوعات

- لا تنقل أو تعدل أو تعيد تسمية أو تحذف `raw/` أو الأصل في `new/`.
- لا تعتبر `processed` أو وجود route record مساويًا لـ`domain_done`.
- لا تدمج التكرار بالتشابه أو الاسم فقط.
- لا تنشئ نسخة غير متحققة أو symlink لتجاوز سياسة المسار.
- لا تغلق التغطية بإخفاء uncertain أو quarantine أو delta غير محسومة.
- لا تنشئ Claims أو Concepts أو Masters بدل وكلائها وبواباتها.
- لا تستخدم Codex في التنفيذ أو التخطيط أو التحقق.
