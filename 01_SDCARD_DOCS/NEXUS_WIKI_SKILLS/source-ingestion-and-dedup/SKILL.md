# إدخال المصدر وإزالة التكرار

## الهدف

حوّل كل ملف إلى هوية قابلة للتتبع دون تعديل المصدر الخام أو الادعاء بأن التسجيل يساوي الفهم.

## عقد 2026-10-10

اقرأ [R/T/C/K/M/QA](../INDEX.md) و`<alignment_path>` والملحق في
`<user_messages_path>` مع تعليمات `<wiki_root>` وschema قبل الكتابة.

- R/`route_done` قبل extraction جائز بعد full semantic read وتصنيف ونسخة
  مستقلة byte-exact متحققة في `done/<domain>/<subdomain>/` افتراضيًا؛ ليست
  symlink/hardlink. `source_refs` فهارس ثانوية فقط، وdone لا تعني domain_done.
- الفرز لأي domain جائز؛ المعرفة في `current_domain` فقط والباقي `queued`،
  لا quarantine إلا لفساد/تعذر قراءة/هوية. غموض الصلة uncertain، لا عزل سلامة.
- أثناء القراءة الاستخراجية سجل terms وcandidate Claims معًا بمواضعها دون
  انتظار المجال كله. Concepts تعتمد أدلة مراجعة، لا تعريفات مختلقة.
- `source_done` استخراج كامل terms/Claims مع QA بلا Concepts أو Master؛
  `subdomain_extraction_done` لا يعوض `domain_terms_complete` لكل المجال وكل
  فروعه قبل أي Master حتى الصغير. لا sample أو snapshot تستبعد مرشحًا بلا قرار.
- احفظ اختلاف الآراء مع scope؛ وصول `delta` يجعل التغطية `stale` ويُجدول في
  queue. فقط `domain_done` يجيز معرفة التالي؛ لا فتح مجالين أو حذف الخام.

## المدخلات والمخرجات

- المدخلات: `<wiki_root>`, `<input_roots>`, `<source_records>`, `<manifest_path>`،
  مع السماح بقراءة raw في مكانه دون نقله. المسارات المسجلة نسبية داخل الجذر.
- المخرجات: هوية وSHA-256 وcanonical وduplicate links، ثم تسليم إلى مهارة
  lifecycle للقراءة الدلالية والتوجيه والنسخ والتحقق؛ لا ادعاء source_done من الجرد.

## الإجراء

1. اقرأ `AGENTS.md` و`SCHEMA.md` قبل أي كتابة.
2. تحقق من path بلا traversal أو خروج من الجذر، واحسب SHA-256 لكل البايتات
   الأصلية قبل التطبيع. قارن الحجم والبصمة قبل/بعد وأوقف الملف المتغير. لا
   تحفظ content_hash وهمية في Source قبل قياسها.
3. افصل هوية المصدر وحالة routing وحالة extraction وحالة المعرفة queued/active
   في workflow. لا تضف registered أو source_done إلى Source.status؛ استخدم
   `new|processed|quarantined` إن كانت قيم schema المعتمدة. processed ليس اكتمال معرفة.
4. اعتبر الملفات ذات البصمة نفسها نسخة byte-exact؛ لا تحذفها. اختر canonical وسجّل البدائل.
5. لا تعتبر تطابق العنوان أو التشابه النصي دليلًا على التطابق؛ اطلب بصمة أو مراجعة.
6. افحص الدفعة وسجلات المصدر وmanifests ونسخ done؛ canonical قائم متحقق أولًا،
   ثم الأقدم المسجل، ثم المسار المعجمي. الاسم نفسه ببصمتين ليس duplicate؛
   التشابه وحده uncertain. المرجع المفقود ليس إثباتًا للتكرار.
7. سجل copy_path وبصمتها واستقلالها بعد R. أعد استخدام النسخة المتطابقة ولا
   تنشئ مصدرًا أو نسخة تصنيف ثانية لنفس المحتوى. تبقى مسارات الأصل والنسخ
   المكررة محفوظة ولا تُعد أدلة مستقلة. سجل الفشل وسببه في `<run_report_path>`.

## بوابة القبول

- المصدر الخام لم يتغير.
- `source_path` نسبي إلى جذر الويكي وقابل للحل.
- `content_hash` ثابت ويمكن إعادة حسابه.
- `status` لا يخلط بين `processed` و`complete`.
- كل نسخة بديلة مرتبطة بالمصدر canonical.

## ممنوعات

- لا تنقل أو تحذف raw.
- لا تستخرج قاعدة من اسم الملف.
- لا ترفع `processed` إلى `complete` تلقائيًا.
- لا تخفِ الملفات غير القابلة للقراءة.
- لا تستخدم Codex، ولا تعزل queued أو رأيًا مختلفًا لمجرد تأجيله أو اختلافه.

## التشغيل مع Corpus كبير

قسّم الإدخال إلى دفعات ثابتة، احفظ checkpoint بعد كل دفعة، واجعل العملية idempotent: إعادة التشغيل لا تنشئ سجلًا ثانيًا لنفس البصمة.

اربط checkpoint بالبصمات وsnapshot وdelta الجديدة. لا تعتبر دفعة مكتملة كل
المجال؛ stale تُراجع قبل Master أو انتقال، وغير النشط يبقى queued.

## حالات تحقق متوقعة، لا نتائج منفذة

- نفس البصمة بمسارين: canonical واحد وسجل duplicate؛ لا حذف أو تضخيم أدلة.
- queued سليم القراءة: R والنسخة مسموحان، extraction ممنوع إلى حين دوره.
- hash ناجح دون full semantic read: R غير ناجحة.
- extraction كامل وQA ولا Master: source_done ممكن، لا domain_done تلقائي.
