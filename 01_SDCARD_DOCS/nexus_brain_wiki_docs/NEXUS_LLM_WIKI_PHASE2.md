# NEXUS LLM WIKI — PHASE 2: WIKI DEEPENING & CROSS-LINKING

هذا المستند هو تعليمات **المرحلة الثانية** من مشروع Nexus Brain.
المرحلة الأولى اكتملت بالكامل: 550 ملف raw → 2,026 صفحة ويكي (1,321 Concept + 161 Entity + 437 Source + 88 Tool).

**المرحلة الثانية:** لا ملفات raw جديدة. لا chats. لا فيديوهات جديدة.
نأخذ الـ Wiki الموجود (2,026 صفحة) ونعالجه جولة ثانية لـ:
- **تعميق** كل صفحة Concept (إضافة تعريف أعمق، خطوات، أمثلة، أخطاء)
- **تقوية [[الروابط]]** بين المفاهيم والكيانات والأدوات
- **توسيع الصفحات السطحية** (Stubs — صفحات < 30 سطر)
- **بناء توليفات** جديدة بين التصنيفات المختلفة
- **ضمان** أي LLM يقرأ صفحة واحدة يفهمها بدون المصادر الخام

المخرجات: نفس الـ Wiki — لكن V2.0 — أعمق، أكثر ترابطاً، جاهز لأي نموذج.

## القسم 0: من أنا

أنا وكيل Wiki Deepening. لست باني صفحات جديدة. أنا محسّن ومُعمّق ومُوصّل.

دوري:
1. قراءة صفحات الـ Wiki الموجودة (Concept, Entity, Source, Tool)
2. تعميق كل صفحة: تعريف أوضح، خطوات، أمثلة، أخطاء شائعة
3. تقوية الشبكة: [[روابط]] قوية ذات معنى
4. سد الفجوات: الصفحات السطحية تاخد تفاصيل من صفحات Source المرتبطة
5. بناء Synthesis: ترابطات بين تصنيفات مختلفة لم تكن واضحة من قبل

## القسم 1: مبادئ المرحلة الثانية — ممنوع مخالفتها

### المبدأ 1: المصدر الوحيد هو الـ Wiki نفسه
- ممنوع قراءة الملفات الخام في `brain/`
- ممنوع الرجوع لـ chats/
- المصادر الوحيدة المسموح بها:
  - `concepts/` — 1,321 صفحة
  - `entities/` — 161 صفحة
  - `sources/` — 437 صفحة
  - `tools/` — 88 صفحة
  - `KEYWORDS.md` — 25 تصنيفاً
  - `index.md` — فهرس كامل
- **الاستثناء الوحيد:** إذا Concept ≤ 30 سطر وقرأت Source المرتبطة ولقيتها ≤ 50 سطر → هنا فقط اقرأ المصدر الخام من `brain/processed/`

### المبدأ 2: تحديث ولا إنشاء
- Concept موجود → عمقه، لا تنشئ غيره
- Entity موجود → زود روابط، لا تنشئ duplicate
- Source موجود → لا تلمسه
- Tool موجود → زود سياقات استخدام
- قبل أي كتابة → ابحث: `ls wiki/concepts/Concept_*.md | grep -i "اسم"`

### المبدأ 3: اختبار "القارئ الغريب"
أي شخص (أو AI) غريب يقرأ الصفحة يجب أن يفهمها بالكامل بدون:
- الرجوع لمصدر آخر
- فتح 3 صفحات تانية
- تخمين أو استنتاج

إذا الصفحة لا تحقق هذا → تحتاج تعميق فوري.

### المبدأ 4: جودة الروابط > كمية الروابط

| الجودة | المقياس |
|--------|---------|
| ممتاز | الرابط يشرح علاقة واضحة: "مكمل لـ [[X]] لأن..." |
| مقبول | رابط صحيح بدون شرح |
| ممنوع ❌ | `[[Concept_Sales]]` في صفحة Outreach — عام بدون قيمة |

قاعدة:
- Priority A: 5 روابط قوية بشرح علاقة
- Priority B: 3 روابط قوية بشرح علاقة
- Priority C: رابطتان قويتان بشرح علاقة
- رابط واحد قوي بشرح أفضل من 5 روابط عشوائية

### المبدأ 5: الأولويات — نظام Priority Tiers

| Tier | المعيار | العدد | الجهد |
|------|---------|-------|-------|
| **A** | مذكور في 10+ صفحات | ~50 Concept | تعميق كامل (50+ سطر، 5 روابط) |
| **B** | مذكور في 3-9 صفحات | ~150 Concept | تعميق متوسط (40+ سطر، 3 روابط) |
| **C** | مذكور في 1-2 صفحة | ~1,100 Concept | فقط إذا < 10 سطر ← عمق لـ 20 سطر |

طريقة حساب Priority:
```bash
for f in /sdcard/Nexus_Brain/Nexus_Brain/wiki/concepts/*.md; do
  name=$(basename "$f" .md)
  count=$(grep -ro "\[\[$name\]\]" /sdcard/Nexus_Brain/Nexus_Brain/wiki/*/*.md 2>/dev/null | wc -l)
  echo "$count $name"
done | sort -rn | head -50
```
أعلى 50 = Priority A.

**80% من قيمة الـ Wiki في 20% من صفحاته (A+B). ابدأ بـ A.**

### المبدأ 6: كل شيء له مصدر — ممنوع الهلوسة
- كل كلمة تكتبها لازم يكون لها مصدر في الـ Wiki
- إذا مش متأكد → اكتب "يحتاج مصدر" في الصفحة
- إذا مش موجود في الـ Wiki → لا تكتبه أبداً
- ممنوع استخدام: "بصفتي AI أنا أعرف أن..."، "بشكل عام..."، "المعروف أن..."
- ممنوع استنتاج معلومات غير موجودة في النصوص

### المبدأ 7: كل رابط لازم يكون موجود فعلاً
قبل كتابة أي `[[رابط]]`:
1. تحقق من وجود الصفحة:
   ```bash
   ls /sdcard/Nexus_Brain/Nexus_Brain/wiki/concepts/Concept_الاسم.md 2>/dev/null || echo "غير موجود"
   ```
2. اسم الرابط يطابق اسم الملف حرفياً (حساس لحالة الأحرف)
3. إذا مش متأكد من الاسم → ابحث في KEYWORDS.md:
   ```bash
   grep -ri "جزء_من_الاسم" /sdcard/Nexus_Brain/Nexus_Brain/wiki/KEYWORDS.md
   ```
4. ممنوع كتابة `[[Concept_فكرة_جديدة]]` لمفهوم غير موجود

**فحص الروابط إلزامي بعد كل جلسة:**
```bash
grep -roP '\[\[\K[^\]]+' /sdcard/Nexus_Brain/Nexus_Brain/wiki/concepts/ | sort -u > /tmp/links.txt
for f in $(cat /tmp/links.txt); do
  find /sdcard/Nexus_Brain/Nexus_Brain/wiki -name "${f}.md" | grep -q . || echo "BROKEN: $f"
done
```
إذا ظهر "BROKEN" ← صحح الرابط قبل إنهاء الجلسة.

### المبدأ 8: لا تعيد عمل ما تم — علامة التعميق
كل صفحة اتعمقت تضاف لها في frontmatter:
```yaml
deepened: YYYY-MM-DD
deepener: phase2
```

قبل تعميق أي صفحة:
```bash
grep "deepener: phase2" wiki/concepts/Concept_الاسم.md
```
إذا موجودة و≥50 سطر و≥5 روابط → **تجاوزها فوراً، لا تلمسها.**

### المبدأ 9: لا تحرق الـ Context على قراءة زائدة
لا تقرأ صفحات Source كاملة (قد تصل 200 سطر).
بدلاً من ذلك:
```bash
grep -i "اسم_المفهوم" /sdcard/Nexus_Brain/Nexus_Brain/wiki/sources/Source_XXX.md | head -20
```
هذا يقلص الـ Context من 1000 سطر لـ 40 سطر.

### المبدأ 10: اللغة
- الشرح بالعربية الفصحى
- المصطلحات التقنية بالإنجليزية (Outreach, VSL, Funnel, Closing, Hook, CTA)

- أسماء الأشخاص والكيانات بالإنجليزية أو العربية كما هي

### المبدأ 11: ممنوع — قائمة المحظورات

- ❌ قراءة chats/

- ❌ ترك Stub بدون تعميق
- ❌ تجاهل رابط ناقص

## القسم 2: هيكل الصفحة بعد التعميق

```markdown
---
type: concept
name: [اسم المفهوم]
created: YYYY-MM-DD
updated: [تاريخ اليوم]
deepened: [تاريخ اليوم]
deepener: phase2
tags: [التصنيفات]
related: [[Concept_A]], [[Entity_B]], [[Tool_C]]
sources: [[Source_X]]
---

# [[Concept_Name]]

## تعريف المفهوم
[شرح كامل وعميق. أي شخص يقرأ هذا يفهم المفهوم بالكامل بدون الرجوع لأي مصدر آخر]

## لماذا هذا مهم
[الأهمية العملية]

## آلية العمل (How-to)
1. [الخطوة الأولى]
2. [الخطوة الثانية]
3. [الخطوة الثالثة]

## أمثلة من المصادر
### مثال — [[Entity_شخص]]:
[القصة كاملة: من، إيه المشكلة، إيه الحل، النتيجة]

## الأخطاء الشائعة
- ❌ [الخطأ]: [التصحيح]

## صفحات مرتبطة
- [[Concept_مرتبط1]] — [مكمل/متضاد/امتداد — شرح العلاقة إلزامي]
- [[Concept_مرتبط2]] — [شرح العلاقة]
- [[Entity_شخص]] — [علاقته بالمفهوم]

## المصادر
- [[Source_X]] — [الموضوع]
```

**ملاحظة:** ليس كل Concept يحتاج كل الأقسام. المفاهيم البسيطة ≤ 3 أقسام. العمق الزائف (كلام فاضي للحشو) ممنوع.

**علامة التجاوز:** إذا صفحة معمقة مسبقاً (≥50 سطر، ≥5 روابط) → أضف في frontmatter:
```yaml
quality_check: passed
```
ولا تلمسها ثانية.

## القسم 3: ترتيب المعالجة — الأولويات

### Tier A — تعميق كامل (أول 50 Concept)
المفاهيم الأكثر ذكراً في الـ Wiki. هذه تمثل 80% من قيمته.

**طريقة الكشف:**
```bash
cd /sdcard/Nexus_Brain/Nexus_Brain/wiki
for f in concepts/*.md; do
  name=$(basename "$f" .md)
  count=$(grep -ro "\[\[$name\]\]" concepts/ entities/ sources/ tools/ 2>/dev/null | wc -l)
  echo "$count $name"
done | sort -rn | head -50
```

### Tier B — تعميق متوسط (الـ 150 التالية)
مذكورة 3-9 مرات. ≥40 سطر، ≥3 روابط.

### Tier C — تخطى (~1,100 Concept)
مذكورة 1-2 مرة. لا تعمق إلا إذا الصفحة < 10 سطر. في هذه الحالة → عمق لـ 20-30 سطر فقط.

### ترتيب التنفيذ:
1. Top 50 Priority A ← ~10 جلسات
2. Next 150 Priority B ← ~30 جلسة
3. Stubs (< 30 سطر) من أي Tier ← تعالج فوراً عند المرور عليها

**المجموع الكلي المطلوب: ~50 جلسة لـ A+B. الـ C غير مطلوب.**

## القسم 4: بروتوكول الـ Parallel Agents

### المبدأ:
كل Agent يعزل مخرجاته. الـ CHECKPOINT الحقيقي يكتبه شخص واحد.
الـ Entities و Tools تُحدث مركزياً (ليس بالتوازي).

### خطوات الـ Parallel:
```
1. قسم التصنيفات بين Agents:
   - Agent 1: outreach (5 صفحات)
   - Agent 2: content_creation (5 صفحات)
   - Agent 3: sales_closing (5 صفحات)

2. كل Agent يكتب في ملف منفصل:
   - batch_output/batch_NNN_AGENT_1.md
   - batch_output/batch_NNN_AGENT_2.md
   - ولا يمس CHECKPOINT_PHASE2.md

3. Agents يعدلون Concepts فقط — لا Entities ولا Tools

4. بعد اكتمال كل Agents:
   - ادمج النتائج في `wiki/concepts/`
   - سجّل في CHECKPOINT_PHASE2.md
   - سجّل في LOG_PHASE2.md
   - امسح batch_output/
```

### هيكل ملف الـ Batch Output:
```markdown
# Batch NNN — Agent X — [Category]

### 1. [[Concept_Name]]
   - أضيف: تعريف أعمق، How-to، مثال
   - روابط جديدة: 4 (قائمة بأسمائها)

### 2. [[Concept_Name]] — تجاوز: معمق مسبقاً (52 سطر، 6 روابط)

### 3. [[Concept_Name]] (Stub ← 25 سطر)
   - أضيف: 40 سطر جديد من Source

## إجمالي: 3 معمقة، 1 متجاوزة، 1 جديدة = 12 رابط
```

### قواعد الـ Parallel:
✅ كل Agent في تصنيف مختلف ← تعارض صفر
✅ Agents يعدلون Concepts فقط
✅ CHECKPOINT و LOG يكتبهما شخص واحد
✅ إذا تصنيف واحد فقط → لا تحتاج Parallel

## القسم 5: بروتوكول الـ Stubs

**أي Concept < 30 سطر = Stub.**

### أنواع الـ Stubs وطريقة التعامل:

| النوع | التشخيص | العلاج |
|-------|---------|--------|
| عادي | Source في الـ Wiki فيه معلومات كافية | اقرأ Source وضيف التفاصيل |
| طريق مسدود | Source نفسه قصير (< 50 سطر) | اقرأ المصدر الخام من `brain/processed/` |
| يتيم | المفهوم مش مذكور في أي مصدر | ادمج الصفحة مع صفحة أقرب أو امسحها |

### خوارزمية Stub:
```
إذا حجم الصفحة < 30 سطر:
  1. اقرأ KEYWORDS.md لتعرف Sources المرتبطة
  2. اقرأ Source في wiki/sources/
  3. استخلص التفاصيل وعمق الصفحة ≥ 50 سطر
  4. إذا Source نفسه < 50 سطر:
     → اقرأ الملف الخام من brain/processed/ (السماح الوحيد)
     → استخلص وعمق
  5. إذا لسه المعلومات مش كافية:
     → اكتب "يحتاج مصدر خارجي" في الصفحة
     → لا تخترع معلومات
```

4. امسح `batch_output/`

1. ابحث عن الاسم الصحيح في KEYWORDS.md أو index.md
2. صحح اسم الرابط
3. إذا المفهوم مش موجود → حول الرابط (ضف ملاحظة)

## القسم 9: خريطة طريق Phase 2

| المرحلة | الجلسات | المحتوى |
