# SYS_10 — نظام الفهارس (Index System)

## 1. الغرض
جعل كل مجلد في الويكي قابلاً للاسترجاع الذكي بلا قراءة كل ملفاته.
كل مجلد يحمل ملف INDEX يعرض أسئلة الاسترجاع (retrieval_questions) التي يجيب عنها،
وحدوده (limitations)، وحالته الصريحة.
الفهرس خادم للقارئ لا مالك للمعرفة.

المصدر الحاكم: `/sdcard/NEXUS_LLM_WIKI/systems/17_FOLDER_INDEX_CONTRACT.md`.

## 2. ما نأخذه (المصادر)
- عقد INDEX لكل مجلد:
  قسم `retrieval_questions` (الأسئلة التي يجيب عنها المجلد)،
  وقسم `limitations` (ما لا يجيب عنه وأين يبحث بدلاً من ذلك)،
  وحالة صريحة واحدة من: `pending` (لم يبدأ)، `partial` (جزئي)،
  `stale` (متقادم — المجلد تغير بعد آخر تحديث للفهرس).
- الحد الأدنى لمدخل الفهرس لكل ملف:
  `id` (المعرف)، `kind` (النوع)، `path` (المسار)، `title` (العنوان)،
  `function` (الوظيفة)، `domain` (النطاق)، `subdomain` (النطاق الفرعي)،
  `scope` (النطاق الجغرافي/الزمني)، `status` (الحالة)،
  `coverage_status` (حالة التغطية)، `snapshot_id` (معرف اللقطة)،
  `updated` (تاريخ التحديث).
- المسار العكسي للإسناد:
  Master ← Concept ← Claim ← `source_id` —
  كل مستوى يشير للمصدر الذي تحته.
- استثناء `raw/`:
  مجلد المواد الخام (raw) غير قابل للتغيير (immutable) ولا يُفهرَس بالمدخل الكامل؛
  يُكتفى بفهرس خفيف يذكر وجوده وحدوده.
- الفهرس يعرض حالة مشتقة من الملفات ولا يملك `active_domain` —
  ملكية النطاق النشط ليست له.

## 3. ما نتجنبه
- فهرس إنشائي يعدد الملفات بلا أسئلة استرجاع (فهرس أرشيف لا فهرس معرفة).
- فهرس يدّعي الاكتمال والمجلد تغيّر بعده (حالة `stale` مكتومة).
- مدخل بلا `function` أو بلا `status` — مدخل ناقص يضلل المسترجع.
- فهرس يقرر «النطاق النشط» ويتصرف كمالك للمعرفة بدل خادم لها.

## 4. القواعد التنفيذية
- **R01 — INDEX إلزامي لكل مجلد:**
  كل مجلد محتوى (غير `raw/`) يحمل `INDEX.md` يبدأ بثلاثة أقسام:
  `retrieval_questions`، `limitations`، والحالة الصريحة
  (`pending` / `partial` / `stale`).
- **R02 — الحد الأدنى للمدخل:**
  كل مدخل في الفهرس يحمل الحقول الاثني عشر
  (id, kind, path, title, function, domain, subdomain, scope, status,
  coverage_status, snapshot_id, updated).
  مدخل ناقص يُوسم `incomplete` ويُستثنى من الاسترجاع.
- **R03 — المسار العكسي محفوظ:**
  من أي مدخل فهرس يمكن النزول:
  الماستر ← مفاهيمه ← ادعاءاته ← `source_id` في `raw/`.
  سلسلة مقطوعة = المدخل معيب.
- **R04 — حالة الفهرس تُحدَّث مع المجلد:**
  أي تغيير في ملفات المجلد يقلب حالة الفهرس إلى `stale` حتى يُحدَّث؛
  الفهرس المتقادم يُعلن تقادمه ولا يدّعي الصلاحية.
- **R05 — `raw/` استثناء صريح:**
  مجلد `raw/` غير قابل للتغيير (immutable)؛
  فهرسه خفيف (وجود وحدود فقط) والمدخل الكامل غير مطلوب.
- **R06 — الفهرس خادم:**
  الفهرس يعرض حالة مشتقة من ملفاته
  ولا يملك `active_domain` ولا أي سلطة قرار معرفي؛
  القرار للأنظمة (SYS_01–SYS_09).

## 5. معيار القبول
- `grep -c "retrieval_questions" systems/SYS_10*.md` ≥ 2.
- كل مجلد محتوى يحمل فهرساً بحالة صريحة
  ومدخلات كاملة الحقول الاثني عشر
  ومساراً عكسياً سالكاً حتى `source_id`.
