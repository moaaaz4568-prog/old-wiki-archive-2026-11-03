# SYS_13 — بروتوكول تفويض المهام للوكلاء (Delegation Protocol)

**المرجع:** NEXUS_OS_COMPREHENSIVE_SYSTEMS_BLUEPRINT.md §3.13 · قاعدة المالك: "شغل ايجنتس تشتغل مكانك" (تكررت 100+ مرة)

## §1 توزيع الأدوار

- **النموذج المشرف:** يخطط، يوزع، يراجع. لا ينفذ الشغل الثقيل بنفسه (قراءة مئات الملفات، كتابة ضخمة).
- **الوكلاء المنفذون:** يقرؤون، يستخرجون، يكتبون، يصنفون — حسب بريفات محددة.
- **الحد الأقصى المتوازي:** 1-3 وكلاء في كل مرة (درس فشل إدارة 12 دفعة واحدة — 10_FULL_CONTEXT.md §2 التجربة 2).

## §2 صيغة البريف الإلزامية

كل تكليف لوكل يحتوي:

```markdown
## المهمة: [سطر واحد محدد]
## السياق: [لماذا هذه المهمة؟ أي قسم تخدم؟]
## الخطوات:
1. [خطوة] — السبب: [لماذا]
2. ...
## ما قد يفشل: [نقص مصادر؟ حدود سياق؟ انزلاق آيس بريك؟] وكيف تتفادى
## معايير القبول: [قابلة للتحقق — ملفات محددة، أقسام ممتلئة، فحوص تمر]
## القواعد الملزمة: عربية أصيلة، ممنوع حذف، كل ادعاء بمصدر path:line،
##                  ممنوع تحويل تكتيك لقانون، ممنوع TODO/placeholders
## التسليم: [أين تكتب المخرج؟ بصيغة ما؟]
```

## §3 المراجعة الإلزامية (4 أسئلة) قبل اعتماد مخرج أي وكيل

1. «لو أنا نفّذت المهمة — كنت طلّعت نفس النتيجة؟»
2. «إيه اللي ممكن يتحسن؟» — نواقص محددة (ملف/سطر/سلوك).
3. «هل النتيجة تلبّي معايير القبول 100%؟» + **الدليل**: أمر شُغّل ومخرجه — ادعاء الوكيل ليس دليلاً.
4. «لو أنا المالك — أسلّم ده كشغل محترف؟»

+ **تحقق عملي إجباري:** المشرف يشغّل أوامر الاختبار بنفسه (فحص التلوث، عد الأسطر، فتح الملفات).

## §4 قواعد ثابتة

- **حزمة الوكيل الواحد ≤ 25 مفهوماً (20-25 مفهوماً كحد أقصى):** درس NB2 الموثق — شريحة 200 مصطلح قتلت 10/12 وكيلاً (استهلاك 177-218k token للناجيين)، والحل المعتمد: 20-25 مفهوماً/وكيل + بناء حتمي سكريبت للكميات الضخمة + وكلاء للدمج الدلالي فقط. (المصدر: NB2/00_SYSTEMS/LOG.md:87,110)
- كل مهمة = نطاق واحد + معيار قبول واحد.
- المهام المنفذة متوازية؛ القرارات المعمارية متسلسلة.
- كل رقم/اسم/سطر في أي تقرير = مصدر حقيقي `path:line`. ممنوع التخمين.
- لو فشل الوكيل: صرّح بالفشل + السبب + البديل. ممنوع تغليف الفشل بنجاح (درس التجربة 3: وكلاء خلفيون يفشلون بصمت).
- ممنوع الحذف بأي أداة (rm/rmdir/shred/trash) — التعديل بالإضافة والتحديث فقط.

## §5 التعامل مع فشل البنية التحتية للوكلاء

إذا فشلت أداة التفويض (spawn ثم error صامت — كما حدث فعلاً في جلسة 2026-10-24):
1. أعلن الفشل صراحة في تقرير التقدم.
2. انتقل للبديل الموثق (AGY عبر agy-director.mjs) أو نفّذ مباشرة.
3. **القاعدة الحاكمة:** إنجاز الملفات الملموسة أهم من آلية التنفيذ — المالك يسأل "فين الملفات؟" لا "أي أداة استخدمت؟".
