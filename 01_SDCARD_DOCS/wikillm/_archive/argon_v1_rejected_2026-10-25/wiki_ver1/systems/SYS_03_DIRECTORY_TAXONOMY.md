## §1 الشجرة الكاملة

```
wiki_ver1/
├── README.md                  # الدليل الشامل

├── systems/                   # 15 نظاماً تشغيلياً SYS_01-15
├── domains/                   # مجالات المعرفة
│   ├── INDEX.md               # خريطة المجالات
│   ├── sales/                 # المبيعات
│   │   ├── 01_discovery_qualification/   # الاكتشاف والتأهيل

│   ├── outreach/              # الأوتريتش
│   │   ├── 01_cold_email_systems/        # أنظمة البريد البارد
│   │   └── 02_icebreakers_hooks/         # كسر النمط الإدراكي
│   ├── pricing_offers/        # العروض والتسعير
│   │   └── 01_grand_slam_offers/         # العروض التي لا تقاوم

└── tools/                     # nexus_rag.py
```

## §2 دور كل مسار

| المسار | الدور | القاعدة |
|---|---|---|
| `raw/` | المصادر الخام الأصلية | **محمي 100%** — لا تعديل ولا حذف أبداً. سياسة الحماية في SOURCE_MANIFEST.tsv |
| `intake/` | المصادر الجديدة قبل التصنيف | تُقرأ وتُصنف إلى domains ثم تُسجل دورة حياتها |
| `domains/<مجال>/<قسم>/` | المعرفة المعالجة | INDEX + PLAYBOOK + TERMS + SOURCES_CATALOG + CONTINGENCY_MATRIX |
| `systems/` | قوانين التشغيل | تُقرأ قبل أي عمل، وتُعدل فقط عند ظهور مشكلة جديدة (SYS_15) |
| `tools/` | أدوات Python | استرجاع سريع بأقل توكنز |

## §3 قاعدة الفهارس

كل مجلد — بلا استثناء — يحتوي `INDEX.md` يشرح: وظيفة المجلد، قائمة ملفاته ووظيفة كل ملف، وأين تذهب لو كنت تبحث عن كذا. (المصدر: رسالة المالك #51 لـ GPT-6: "فهرس يقول للايجنت كل ملف عبارة عن ايه")

## §4 التوسع الأفقي والرأسي

- **أفقي:** مجال جديد = مجلد جديد في `domains/` بنفس البنية الداخلية الخماسية.
- **رأسي:** قسم جديد داخل مجال = مجلد `NN_name/` جديد مع تحديث INDEX الأب.
- عند 100K+ ملف: تتحول الأقسام الضخمة لماسترز فرعية (انظر SYS_15 §3 وNEXUS_WIKI_SCALABLE_ARCHITECTURE.md §3).
