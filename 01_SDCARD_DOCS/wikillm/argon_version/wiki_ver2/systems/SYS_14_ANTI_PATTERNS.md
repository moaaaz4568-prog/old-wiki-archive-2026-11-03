# SYS_14 — الأنماط المضادة: سجل الأخطاء المحظورة وأخطر السيناريوهات

> النظام الحاكم لمنع تكرار الأخطاء الموثقة: كل نمط مضاد هنا حدث فعلاً في تجارب سابقة موثقة، وكل سيناريو له اكتشاف مبكر بأمر وحماية منفَّذة. تكرار أي منها = فشل مؤسسي.

## §1 خطأ الآيس بريك — الخطأ التأسيسي

**ماذا حدث:** مثال فردي من خبير (تكرار اسم البراند 3 مرات في الآيس بريك) حوّله نموذج إلى قاعدة مطلقة، فكررها عبر كل المخرجات، ورفض المالك النظام كله. هذا الخطأ هو السبب التأسيسي لوجود المشروع بأكمله.

**الحماية المنفَّذة:**
- الإدراك الرباعي إلزامي لكل قاعدة: (سيكولوجيا → مبدأ → تكتيكات موسومة بسياقها → حدود فشل).
- القاعدة بلا «متى تفشل» **لا تُكتب أصلاً** — لا تُكتب ثم تُصحح.
- اختبار «يجب دائماً»: أي صياغة إلزامية مستمدة من مثال واحد = إنذار فوري.
- المثال ليس قاعدة — Do Not Inflate Examples (دستور AGENTS.md، القاعدة 4).

## §2 أخطر 10 سيناريوهات من المحاكاة

### سيناريو 1: النجاح الكاذب (81 شكوى موثقة)
- **ماذا يحدث:** الوكيل يكتب «تم إنجاز المهمة» بينما القرص فارغ أو ناقص؛ المخطط يبني الموجة التالية على أساس كاذب. أخطر سيناريو مطلقاً — قتل 5 تجارب متتالية.
- **الاكتشاف المبكر:** `find domains -name "*.md" -newer checkpoint | wc -l` — صفر ملفات جديدة بعد «انتهيت» = نجاح كاذب.
- **الحماية:** قاعدة R09 — كل ادعاء إنجاز يلزمه أمر shell شُغِّل ونتيجته مكتوبة، والمراجع يشغّل الأمر بنفسه.

### سيناريو 2: تحويل مثال لقاعدة
- **ماذا يحدث:** تكتيك فردي ناجح يُوثَّق كقاعدة مطلقة فتنتشر عبر كل المخرجات بصمت (§1 أعلاه).
- **الاكتشاف المبكر:** `grep -rn "يجب دائماً\|دائماً استخدم" systems/ domains/ | wc -l` — كل إصابة تُفحص يدوياً: هل لها حدود فشل؟
- **الحماية:** الإدراك الرباعي + حدّ الفناء لكل وصفة + اختبار الوصفة الميتة.

### سيناريو 3: ماسترز فرعية بلا حاكم عند 100K
- **ماذا يحدث:** عند التوسع تُقسَّم كل ماستر لفرعيات فتظهر 500 ماستر متساوٍ متناقض بلا من يجمعها؛ الوكيل يقرأ 10 فرعيات متناقضة ويخرج بخطة مشوّهة.
- **الاكتشاف المبكر:** `grep -L "M_" master_index.md | wc -l` — كل ماستر فرعي يجب أن يظهر في فهرس ماستر أم واحد.
- **الحماية:** المعمارية الثلاثية (Master Index → Master Parent → Master Sub) — تفصيلها في SYS_15.

### سيناريو 4: بوابات حاجزة تقتل الإنتاج
- **ماذا يحدث:** بنية مثالية بصفر ماستر (درس V3)؛ 3 ملفات من 2,541 (درس GPT-6)؛ كل شيء معلق ببوابات تعليق بلا ترقية.
- **الاكتشاف المبكر:** `find domains -name "PLAYBOOK_*.md" -mtime -7 | wc -l` — صفر مخرجات لأسبوع = إنذار بوابات.
- **الحماية:** بوابات حارسة لا حاجزة + توليف تراكمي فوري + العتبات وظيفية لا كمية.

### سيناريو 5: موت الوكلاء بحزم كبيرة
- **ماذا يحدث:** 10/12 وكيلاً ماتوا بشريحة 200 مصطلح (درس NB2)؛ الموجة كلها تفشل والتقرير يضيع.
- **الاكتشاف المبكر:** مراقبة token لكل وكيل — فوق 150k = إنذار تقسيم قبل الموت.
- **الحماية:** 20-25 وحدة/وكيل + تقسيم KB + append فوري + FIX فوري (SYS_13).

### سيناريو 6: التلوث الصيني (16 ماستر ملوثاً)
- **ماذا يحدث:** نص صيني يتسرب من نموذج أو مصدر مترجم فينتشر بالنسخ بين الملفات؛ المالك يرفض النظام كله.
- **الاكتشاف المبكر:** `python3 -c "import pathlib; print(sum(1 for p in pathlib.Path('.').rglob('*.md') for c in p.read_text(errors='ignore') if '\u4e00' <= c <= '\u9fff'))"` ⇒ يجب أن يكون 0.
- **الحماية:** فاحص آلي في audit.py (بوابة G1 بوزن 25) + عزل فوري + إصلاح من المصدر الأصلي.

### سيناريو 7: انفجار ملفات مجهرية
- **ماذا يحدث:** كل جملة تصير ملفاً مستقلاً؛ آلاف الملفات بحجم كيلوبايتات تستهلك inode وتبطئ كل بحث (درس claims/CLM_*.md).
- **الاكتشاف المبكر:** `find . -type f -size -3k -name "*.md" | wc -l` — نسبة الملفات الصغيرة >60% = إنذار.
- **الحماية:** ملف جامع لكل نطاق + حاجب D01 (التعداد الثلاثي type × بادئة × مجلد) يرفض أي ملف خارج الكيانات الثمانية.

### سيناريو 8: مجلدات فوق 1000 ملف
- **ماذا يحدث:** GitHub يحذف المجلدات الكبيرة صامتاً عند push؛ المستودع المفتوح يفقد محتواه (31 تكراراً موثقاً).
- **الاكتشاف المبكر:** `find . -type d -exec sh -c 'test $(ls "$1" | wc -l) -gt 900' _ {} \; -print` — أي مجلد يقترب من 900 = إنذار.
- **الحماية:** حد صارم ≤900 + شطر تلقائي part_NN بفهرس استرجاع + فاحص قبل كل push.

### سيناريو 9: أرقام متضاربة بلا مصدر
- **ماذا يحدث:** ستة أرقام لنفس الكيان في ثلاثة ملفات (درس NB2)؛ 80% و35% و90% بلا أصل (NEXUS_OS)؛ الرقم المخترع يُنسخ حتى يصير «حقيقة» للنظام.
- **الاكتشاف المبكر:** `python3 tools/count.py --check` — أي رقم بلا أمر قياس أو مخالف للمصدر = ⚠️.
- **الحماية:** قاعدة sima_yi — المصدر الوحيد COUNTS.json + كل نسبة تحدد مقامها (ملف ≠ مفهوم ≠ مصدر مستقل).

### سيناريو 10: هلوسة المصادر (25 معرفاً وهمياً)
- **ماذا يحدث:** الوكيل يستشهد بـSRC_042 أو اقتباس من «فيديو غيث» غير موجود على القرص؛ المعرفة كلها تُبنى على مصادر خيالية.
- **الاكتشاف المبكر:** `for id in $(grep -rhoE 'SRC_[0-9]+' . | sort -u); do find /sdcard/Nexus_Brain -name "$id*"; done | wc -l` — صفر نتائج لمعرف = هلوسة.
- **الحماية:** كل SRC يشير لملف موجود يُثبت بـfind + كل اقتباس بموضع (locator) + فاحص آلي قبل اعتماد أي ماستر.

## §3 القاعدة الجامعة

كل ادعاء له موضع وبصمة، كل رقم له أمر قياس، كل وصفة لها حدّ فناء، كل بوابة لها فاحص، وكل «انتهيت» تعني ملفاً على القرص تحقق منه المراجع بنفسه. الفشل الصامت هو القاسم المشترك: النظام يبدو سليماً والضرر يُكتشف متأخراً — لذلك الدورة الوقائية (audit.py + count.py --check) تُشغَّل قبل كل اعتماد ودفع.
