# 06 — جمع مصادر دورة المبيعات

## الغرض والنطاق

هذا النظام يحوّل corpus المبيعات إلى مجموعة قراءة قابلة لإعادة البناء، من دون نقل
أو تعديل `raw/`. يشمل محادثة البيع، التشخيص، عرض القيمة والتسعير، الإغلاق
الاستشاري، المتابعة، والبريد البارد. الناتج **ترشيح للقراءة** وليس حكمًا بأن
المصدر صحيح أو أن حالته `complete`.

## المدخلات

1. الملفات الموجودة تحت `raw/new/` أو مرجع خام مسجل وفق سياسة المصدر.
2. سجلات `sources/`، وبها على الأقل `source_id`, `source_path`, `content_hash`,
   `media_type`, `language`, `status`.
3. قائمة نطاق المبيعات وكلماتها البديلة، مع قائمة الاستبعادات المعروفة.
4. checkpoint سابق، إن وجد، لتثبيت النسخة والبصمات وعدم إعادة تفسير نتائج قديمة.

## الإجراء

1. احسب SHA-256 للملف واقرأه بترميز UTF-8 مع تسجيل حالات الاستبدال إن حدثت.
2. طابق البصمة أولًا ثم الاسم والمسار؛ الاسم وحده لا يثبت التفرد.
3. أنشئ فهرسًا افتراضيًا للمصادر لا ينسخ `raw`: المسار النسبي، البصمة، الحجم،
   اللغة، درجة الترشيح، الكلمات التي أدت إلى الترشيح، ودرجة الصلة المبدئية.
4. صنّف العنصر `strong` أو `possible` أو `excluded_candidate` لأغراض ترتيب
   القراءة فقط. لا تُستخدم الدرجة كدليل Claim.
5. سجّل النسخ المطابقة والملفات الضعيفة أو خارج النطاق في سجل الاستبعادات مع السبب؛
   لا تحذفها.
6. اجعل القراءة الكاملة تبدأ من `strong`، ثم `possible`، مع عينة مضبوطة من
   المصادر الضعيفة لقياس معدل الإيجابيات الكاذبة.

## المخرجات

### سجل المصدر

كل عنصر يجب أن يحافظ على عقد `Source` في `SCHEMA.md`:

```yaml
type: source
source_id: SRC_YYYYMMDD_slug
title: عنوان المصدر
source_path: raw/new/relative-file.ext
content_hash: sha256:...
media_type: transcript|article|book|conversation|code|other
language: ar|en|mixed
status: new|processed|quarantined
created: YYYY-MM-DD
updated: YYYY-MM-DD
```

### سجل المجموعة

يُحفظ في `collections/sales/` ويحتوي على `collection_id`, `generated_at`,
`scope`, `selection_method`, `raw_policy`, `counts`, و`items`. يحفظ كل `item`
المسار النسبي والبصمة و`source_id` إن كان مسجلًا وسبب الترشيح وحالة القراءة.

### سجل الاستبعاد

لكل استبعاد: `exclusion_id`, `source_path` أو `source_id`, `reason`, `evidence`,
`reviewer`, `created`. أمثلة الأسباب: خارج النطاق، نسخة مطابقة، ملف غير مقروء،
أو خطاب تسويقي بلا مضمون قابل للفحص. لا يُسجل الاستبعاد كرفض Claim.

## بوابات القبول

- **G0 الهوية:** لكل عنصر مسار نسبي وبصمة وحالة؛ لا مسار مطلق ولا `..`.
- **G1 سلامة الخام:** البصمة المحفوظة تطابق الملف، و`raw/` لم يتغير.
- **G2 التفرد:** كل تطابق بصمة معلن؛ لا مصدران متكرران بلا `duplicate_of` أو قرار.
- **G3 الصلة:** يمر كل مصدر قوي بقراءة بشرية، ويكون سبب ترشيح الممكن قابلًا للشرح.
- **G4 اكتمال المجموعة:** لا تسمى المجموعة `complete` بسبب عدد الملفات أو Claim واحد؛
  يلزم تقرير يبين الملفات المفحوصة، غير المفحوصة، والحدود.

## حالات الفشل والتعامل معها

| الحالة | الأثر | الإجراء |
|---|---|---|
| بصمة مفقودة أو متغيرة | لا يمكن تتبع الدليل | أوقف الإدخال، أعد الحساب، وسجل المشكلة |
| مصدر بلا سجل | خطر Claim يتيم | أبقه `unregistered`، لا تستخرج Claim مقبولًا، وأنشئ سجل Source لاحقًا |
| نص غير مقروء أو ناقص | دليل مبتور | `quarantined` مع السبب، ولا تخمّن الجزء المفقود |
| ترشيح مرتفع بسبب كلمة عامة مثل offer | إيجابي كاذب | أعده للمراجعة ولا ترفعه إلى قوي تلقائيًا |
| تكرار بالبصمة | عدّ مضاعف | احتفظ بالمسارات وسجل الأساسي والنسخ التابعة |

## معايير القياس

- **سلامة المصدر:** `مطابقو_البصمة / إجمالي_السجلات` = 100% للقبول.
- **تغطية الفحص:** `المصادر المقروءة دلاليًا / المرشحين`، مع المقام والتاريخ.
- **دقة الترشيح:** عينة من المرشحين القويين التي ثبتت صلتها فعليًا.
- **معدل التكرار المكشوف:** عدد النسخ المطابقة المسجلة / عدد النسخ المكتشفة.
- **زمن الوصول:** من إنشاء المجموعة إلى أول موضع قابل للإحالة.
- **سلامة الخام:** بصمة/قائمة ملفات قبل وبعد، وأي فرق = فشل البوابة.

## checkpoint المطلوب

يسجل `checkpoint_id`, تاريخ التنفيذ، نسخة المجموعة، عدد الملفات، مجموع البايتات،
عدد البصمات الفريدة، حالات المصادر، الاستبعادات، ونتيجة G0–G4. يظل الفرق بين
`processed` في Source وبين اكتمال القراءة الدلالية ظاهرًا.
