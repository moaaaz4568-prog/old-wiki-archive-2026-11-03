# 18 — كتالوج المجالات وترتيب المعالجة

**مراجعة:** 2026-10-10 — عقد ملكية وتصنيف؛ لا تعديل config في هذه المهمة.
**مرجع:** [المواءمة](../reports/sales-proof/MULTIDOMAIN_ALIGNMENT_2026-10-10.md) و[ملحق المستخدم](../reports/sales-proof/USER_MESSAGES_SESSION_EF22.md).

## 1. المرجعية والحدود

- المبيعات وoutreach وردا صراحة؛ pricing_offers وcontent_strategy اختيار تنسيقي للموجة، لا اقتباس تاريخي من المستخدم.
- الترتيب: `sales` ثم `outreach` ثم `pricing_offers` ثم `content_strategy`، لإنجاز المعرفة بالتتابع.
- لا يتطلب الترتيب ممارسة بيع فعلية أو إثبات عرض تجاري أو تعلم السوق قبل السماح ببناء الويكي.
- `config/domain_catalog.json` وحده يعرف المجالات وsubdomains والحدود والأسماء البديلة ونسخة التصنيف.
- `config/processing_order.json` وحده يملك الترتيب والحالة والمجال النشط والقفل؛ لا حالة ثانية داخل catalog.
- لا يُستبدل الملفان بأمثلة هذه الوثيقة؛ يراجع المنفذ التوافق البنيوي قبل أي انتقال فعلي.

## 2. الحدود الموضوعية

| domain | يدخل في النطاق | يحال عندما يكون هو الغرض الرئيسي |
|---|---|---|
| `sales` | اكتشاف الاحتياج، محادثة البيع، معالجة الاعتراض، التفاوض والإغلاق والمتابعة البيعية | إنشاء رسائل تواصل بارد إلى outreach؛ هندسة السعر إلى pricing_offers |
| `outreach` | الاستهداف والتواصل الأولي والقنوات والتسليم والمتابعة قبل الفرصة المؤهلة | إدارة المحادثة البيعية إلى sales؛ استراتيجية المحتوى إلى content_strategy |
| `pricing_offers` | تصميم السعر والقيمة والباقات والضمانات وحدود الخصم وبنية العرض | التعامل مع اعتراض مشترٍ على سعر معروض إلى sales |
| `content_strategy` | أهداف المحتوى والجمهور والمحاور والتخطيط والتوزيع والقياس الاستراتيجي | رسالة cold email إلى outreach؛ مكالمة إغلاق إلى sales |

موضوع «السعر غالٍ» لا يصنف بالكلمة: **دعم price objections مبيعات**؛ **تصميم السعر تسعير**.
القرار من الغرض والسياق والمواضع، لا اسم الملف أو تشابه المصطلحات أو رقم cluster قديم.
حدود المتابعة يحددها السياق: تواصل أولي غير مؤهل outreach؛ متابعة فرصة بيعية sales.
المصدر متعدد الموضوعات له primary واحد وsecondary refs؛ لا تكرار نسخ ولا أدلة مستقلة مصطنعة.

## 3. حقول catalog

المثال مختصر لتوضيح الحقول فقط؛ أقسامه ليست حصرًا فعليًا ولا بديلًا عن catalog القائم:

```json
{
  "schema_version": 1,
  "catalog_revision": "example-v1",
  "updated": "2026-10-10",
  "domains": [
    {"id": "sales", "label": "المبيعات", "scope": "محادثة وفرصة البيع", "excludes": ["هندسة السعر"], "aliases": ["selling"], "subdomains": [{"id": "objection_handling", "scope": "معالجة اعتراض المشتري", "aliases": ["price objections"]}]},
    {"id": "outreach", "label": "التواصل الأولي", "scope": "الوصول إلى عميل محتمل", "excludes": ["إغلاق محادثة بيعية"], "aliases": [], "subdomains": [{"id": "cold_email", "scope": "البريد البارد", "aliases": []}]},
    {"id": "pricing_offers", "label": "التسعير والعروض", "scope": "تصميم السعر والباقات", "excludes": ["رد مندوب على اعتراض قائم"], "aliases": [], "subdomains": [{"id": "pricing", "scope": "تصميم السعر", "aliases": []}]},
    {"id": "content_strategy", "label": "استراتيجية المحتوى", "scope": "تخطيط المحتوى وتوجيهه", "excludes": ["حوار بيع فردي"], "aliases": [], "subdomains": [{"id": "content_planning", "scope": "تخطيط المحاور والتوزيع", "aliases": []}]}
  ],
  "routing_policy": {"primary_routes_per_source": 1, "secondary_refs_allowed": true},
  "change_reason": "مثال تعليمي، ليس حالة مخزون أو قرار ترحيل"
}
```

يلزم كل domain/subdomain: ID مستقر، وصف نطاق، وقواعد استبعاد/حدود كافية؛ aliases لا تنشئ مجلدات جديدة.
subdomain IDs فريدة داخل مجالها؛ هوية القسم الكاملة زوج `domain/subdomain`، لا slug منفرد.
لا أسماء `..` أو فواصل مسار أو IDs مبهمة؛ الرابط القديم يسجل في aliases أو سجل ترحيل لا يطمس.
المجالات الفعلية في الموجة هي الأربعة فقط؛ مادة خارجها تسجل outside-scope مع دليل ولا تُجبر على أحدها.
لا `active_domain` أو حالات gates داخل catalog؛ أمثلة الحالة ومزامنتها في [16](16_SEQUENTIAL_AGENT_ORCHESTRATION.md).

## 4. قرار التصنيف العام

1. اجرد جميع عناصر intake، لا مصادر sales وحدها، وسجل كل مرشح قبل cutoff ومصيره.
2. اقرأ المضمون الدلالي وسجل أدلة الغرض والبنية والسياق بمواضعها وفق [14](14_SOURCE_ROUTING_AND_DONE_TREE.md).
3. قارنه بحدود catalog؛ اقترح primary وsecondary مع أسباب وترجيح قابل للمراجعة.
4. إذا غاب subdomain مناسب أو تعادل المجالان، أبق `uncertain` وقدم اقتراح catalog للمالك فقط.
5. يجوز نسخ مصدر pending والتحقق منه؛ يبقى استخراجه المعرفي مقفلًا حتى يتغير active_domain رسميًا.
6. `pending` ليس quarantine؛ العزل لفشل سلامة/قراءة/هوية أو سبب مستقل موثق، لا لتأخر الدور.
7. يسجل مصير المصدر المختلط كاملًا: وحداته ذات الصلة بالمجال النشط ومراجع بقية الموضوعات.

## 5. تغيير catalog دون تغيير التاريخ

- التغيير يحتاج سببًا ومراجعًا ونسخة قديمة وجديدة وقائمة المجالات/المسارات/snapshots المتأثرة.
- إضافة subdomain لا تعني نقل مصادرها أو بدء معرفتها تلقائيًا؛ إعادة التوجيه مهمة مأذونة مستقلة.
- التسمية القديمة تحل إلى الجديدة بتوثيق واضح؛ لا حذف الأصل ولا نسخ تصنيف ثانوية متكررة.
- اللقطة المغلقة تحتفظ بـcatalog_revision القديمة؛ لا يُعاد تفسير coverage بأقسام جديدة صامتًا.
- تغيير الحدود أو اكتشاف قسم ناقص يطلق delta/invalidation وفق [19](19_NEW_SOURCE_REPROCESSING.md).
- إعادة ترتيب الموجة قرار تنسيق صريح يوثق سببه؛ لا يجعل المجال التالي active بوجود مجال جارٍ.
- إذا اختلفت نسختا catalog في snapshot والحالة، يتوقف الانتقال حتى تقييم التوافق لا بمجرد استبدال النص.

## 6. مثال عام قصير

ملف عنوانه `notes.txt` يقول: «قبل الرد على اعتراض غلاء العرض اسأل عمّا يقارنه المشتري».
في هذا المثال الغرض محادثة اعتراض → sales/objection_handling إن كان القسم مسجلًا؛ ليس pricing بسبب كلمة «غلاء».
إذا كان المتن بدلًا منه يشرح اختيار نموذج اشتراك وحدود الباقات، فالغرض pricing_offers لا محادثة بيع.
إذا اجتمع الغرضان، يُرجّح الرئيسي بدليل وتُحفظ إحالة الآخر؛ وإذا تعادلا يبقى التصنيف uncertain.
المثال يشرح توجيهًا فقط، ولا يُنشئ Claim أو يثبت صلاحية النصيحة كقاعدة أعمال.

## 7. تحقق التكامل

- تحقق مجموعة IDs الأربعة ومطابقة order لها بلا فقد أو تكرار؛ لا تفترض أن ترتيب JSON هو حالة التنفيذ.
- تحقق أن كل primary وsecondary يشير إلى domain/subdomain مسجل أو قرار unresolved ظاهر.
- تحقق أن جميع المرشحين، بما فيهم المستبعدون وخارج المجال، موجودون في manifest الشامل.
- اختبر اسمًا مضللًا ومتنًا واضحًا، وسعرًا في محادثة بيع، ونص تصميم سعر، ومصدرًا متعادل الغرض.
- اختبر مصدر pending صالحًا: route يسمح، extraction يرفض، وquarantine لا تضاف تلقائيًا.
- تحقق من بصمات التكرار: نسخ نفس النص لا تصبح مصادر مستقلة ولا ترفع نسبة تغطية المعرفة.
- لا فحص على config الحقيقي هنا؛ عند التكامل لا يُعلن PASS إلا بأدلة تشغيل المالك ضمن صلاحياته.
