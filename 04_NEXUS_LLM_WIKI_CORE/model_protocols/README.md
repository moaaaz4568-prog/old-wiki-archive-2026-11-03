# بروتوكولات تشغيل النموذج

هذه الطبقة تصف **السلوك الخارجي القابل للملاحظة** عند قراءة المصادر، استخراج المعرفة،
الكتابة، المراجعة، وتنفيذ المهام. وهي بروتوكولات مستقلة عن النموذج: لا تفترض نموذجًا
بعينه، ولا تزعم نقل قدرة خاصة، ولا تطلب كشف سلسلة التفكير الداخلية. المطلوب هو حفظ
قرارات قصيرة وأدلة قابلة لإعادة الفحص.

## قواعد مشتركة

1. **افصل الإجراء عن الدليل:** قول النموذج «قرأت» أو «تحققت» ليس دليلًا كافيًا؛ يجب
   تسجيل المسار، والموضع، والأمر أو الاختبار، والنتيجة.
2. **لا تُعدِّل المصدر الخام:** `raw/` غير قابل للتعديل. اكتب المخرجات في المسار
   المصرح به فقط، وفق [تعليمات الوكلاء](../AGENTS.md).
3. **لا تخلط الحالات:** `route_done` لا يعني `source_done`، ووجود Claim مرشح لا يعني
   قبول المعرفة. راجع [SCHEMA](../SCHEMA.md) قبل إنشاء سجل جديد.
4. **لا تستبدل سلسلة التفكير بتقرير زائف:** يسجل النموذج ملخص قرار، وبدائل مرفوضة
   وسببًا قابلًا للمراجعة، لا chain-of-thought.
5. **المثال ليس قاعدة:** كل مثال يظل موسومًا بسياقه وحدوده، ولا يتحول إلى وصفة عامة
   دون دليل مستقل.
6. **المراجعة مستقلة:** لا يعتمد قرار `PASS` على رسالة العامل أو على ملخص المؤلف
   وحده؛ يلزم فحص المنتج ومصادره.

## ترتيب الاستخدام

1. ابدأ بـ **01** لفهم الطلب وتثبيت النطاق والقيود.
2. إذا كان المدخل مصدرًا، طبّق **02** قبل استخراج أي Claim أو تعريف.
3. طبّق **03** عند تحويل وحدات المصدر إلى نص أو سجلات معرفية.
4. طبّق **04** بصورة مستقلة قبل وصف المخرج بأنه مقبول.
5. استخدم **05** طوال التنفيذ، وعند كل تسليم أو فشل أداة أو handoff.

يمكن تكرار الحلقة؛ لا يعني تكرارها أن الحالة نجحت. الحالة تُحسم فقط بأدلة فحص
مرتبطة بالمخرج.

## اختيار البروتوكول بسرعة

- سؤال غامض أو مهمة طويلة؟ **01 + 05**.
- مصدر طويل أو ادعاء يحتاج اقتباسًا؟ **02 + 03 + 04**.
- نص تسويقي أو تقرير يريد الحفاظ على صوت صاحبه؟ **03** مع فحص عدم الاختلاق.
- مخرج من عامل آخر أو تعديل حساس؟ **04 + 05**.
- تعطل أداة أو انقطاع جلسة؟ **01 + 05**؛ احفظ آخر نقطة مثبتة ولا تعلن النجاح.

## ما يثبت الإجراء

- وجود الملفات الخمسة، ووضوح وظيفة كل ملف، وروابطه إلى العقود ذات الصلة.
- تسجيل مسار الإجراء، والمدخلات، والمخرجات، والاختبارات أو الفحوص الفعلية.
- وجود حدود صريحة لما يثبته كل دليل وما لا يثبته، مع قرار `PASS` أو `RETURN` عند
  المراجعة.

## ما لا يثبته الإجراء

- لا يثبت وجود هذه الوثائق أن كل المصدر قد قُرئ أو أن أي مجال في الويكي اكتمل.
- لا يثبت نجاح أداة بنيوية وحده صحة القراءة الدلالية أو صحة الاقتباس أو اجتياز بوابات
  `T/C/K/M/QA`.
- لا يثبت ملخص النموذج أو انتهاء العملية أو رسالة Agent أن المخرج صالح أو معتمد.
- لا يكشف البروتوكول chain-of-thought ولا يدّعي امتلاك نموذج بعينه لقدرة خاصة.

## ما يجب تسجيله

- `run_id` أو معرّف المهمة، والتاريخ، والدور، والنطاق، والمسارات المسموح بها.
- المصادر أو الملفات المقروءة فعلًا، وبصماتها أو معرّفاتها عند انطباق ذلك، وآخر موضع
  قراءة مثبت.
- القرارات المختصرة، والافتراضات، والبدائل المرفوضة، والأدلة، وأوامر الفحص، وexit code.
- الفجوات، والتناقضات، والفشل، وما يحتاجه التسليم التالي؛ لا تُخفى العناصر غير
  المكتملة.

## مثال محايد صغير

> طلب: «حوّل فقرة عن تجربة منتج إلى سجل قابل للمراجعة».

التطبيق الصحيح: يحدد النموذج المصدر والفقرة وموضعها، يصنفها كتقرير تجربة أو مثال
بحسب النص، يصوغ Claim محدود النطاق مع citation، ثم يمرره إلى مراجعة مستقلة. لا يصوغ
منها قاعدة عامة لمجرد أنها مثال.
